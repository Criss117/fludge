# Welcome to Your New Wails3 Project!

Congratulations on generating your Wails3 application! This README will guide you through the next steps to get your project up and running.

## Getting Started

1. Navigate to your project directory in the terminal.

2. To run your application in development mode, use the following command:

   ```
   wails3 dev
   ```

   This will start your application and enable hot-reloading for both frontend and backend changes.

3. To build your application for production, use:

   ```
   wails3 build
   ```

   This will create a production-ready executable in the `build` directory.

## Exploring Wails3 Features

Now that you have your project set up, it's time to explore the features that Wails3 offers:

1. **Check out the examples**: The best way to learn is by example. Visit the `examples` directory in the `v3/examples` directory to see various sample applications.

2. **Run an example**: To run any of the examples, navigate to the example's directory and use:


## Frontend Stack

`frontend/` is a workspace package (`@fludge/desktop-frontend`) that shares the monorepo tooling:

- **React 19** (`catalog:` in the root `package.json`, same version as the native app)
- **TanStack Router** with file-based routes in `src/routes/`; `src/routeTree.gen.ts` is generated by the Vite plugin and committed
- **Tailwind CSS v4** through `@tailwindcss/vite`, importing `@fludge/ui/globals.css`
- **shadcn** components from the shared `@fludge/ui` package
- **Geist** (sans and mono) served locally by `@fontsource-variable/geist`; it overrides the shared Inter default through the Tailwind theme
- **React Compiler** enabled through Babel (`reactCompilerPreset` in `vite.config.ts`)

Frontend commands (run inside `frontend/`, or from the repo root with `bun run -F @fludge/desktop-frontend <script>`):

| Command               | What it does                                          |
| --------------------- | ----------------------------------------------------- |
| `bun run dev`         | Vite dev server on port 9245 (what `wails3 dev` uses) |
| `bun run build`       | Production bundle, then `tsc --noEmit`                |
| `bun run check-types` | TypeScript only                                       |
| `bun run lint`        | ESLint with the shared `@fludge/config` rules       |
| `bun run lint:fix`    | Same rules with autofix                               |

Linting comes from `@fludge/config/eslint/react`, so the three house rules apply here too: type-only imports must be `import type`, unused imports are removed, and imports are sorted. Prettier runs as an ESLint rule, with the root `.prettierrc` (`@fludge/config/prettier`) plus the Tailwind class sorter.

Add a page by creating a file under `src/routes/` (for example `src/routes/orders.tsx`); the plugin regenerates the route tree on the next dev run or build. `/ui` is a small showcase of the Tailwind and shadcn setup.

### Desktop shell behaviour

`src/styles.css` restores what a Wails window needs on top of the shared palette:

- `html`, `body` and `#root` share a `height: 100%` chain, so `h-full` and `min-h-screen` pages fill the window.
- Chrome text is not selectable (`user-select: none`); inputs, `pre`, `code` and `[contenteditable]` opt back in.
- The background drags the window through `--wails-draggable: drag`, which the Wails runtime reads. Links, buttons and form controls opt out automatically; any other clickable element (menu item, table row) must opt out with the `[--wails-draggable:no-drag]` utility or by adding `--wails-draggable: no-drag`.
- `color-scheme` follows the palette so native controls and scrollbars match the `.dark` variant.

## Project Structure

Take a moment to familiarize yourself with your project structure:

- `frontend/`: React 19 + TanStack Router + Tailwind v4 + shadcn frontend (see Frontend Stack)
- `main.go`: The entry point of your Go backend
- `app.go`: Define your application structure and methods here
- `wails.json`: Configuration file for your Wails project
